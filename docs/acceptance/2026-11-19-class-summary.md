# 2026-11-19 课堂录音验收记录

- 场次：15 分钟课堂（实际录音 **22:51**，11:45 – 12:08），一加 12 / Android 16 / targetSdk 37
- 音频：41.8 MB WAV（16 kHz 单声道）
- 段落：85 段，平均 19.2 s / 段
- 微摘要：12 条；阶段小结：3 条；终稿：`终稿完成（校正 65/85 段，2 段待确认）`
- 报告：已生成，6964 字符，33 条要点，15 条待确认（多数带锚点）

## 监控

每 2 分钟采样 `dumpsys activity services` + WAV 字节数（见下），录音全程 `isForeground=true`，WAV 单调增长：

```

11:49:10 bytes=7,033,644 fgService=1 level=70 temp=313
...
12:07:13 bytes=41,699,244 fgService=1 level=72 temp=307
12:09:13 bytes=43,868,844 fgService=0 level=72 temp=310  (停止录音后)
```

## 质量观察

- 报告确实抓到了数字/人名层面的可疑点，例如：
  - 「今年是中国共产党成立一百零五周年…」——实时稿是「一百四十五周年」，数字自相矛盾（[03:08]）
  - 「冯立言将军 / 洪铁将军」前后矛盾，疑同音错（[18:16] / [19:00]）
  - 「唐探一九零零」「张凌赫刘雨婷」等专名标了待确认
- 阶段小结 3 段（0–9:49 / …）把长课分成可读的阶段，符合 ADR-0003 设计

## 已暴露的缺口

1. **报告要点没有时间锚点**：ADR-0007 的「≥95% 要点可回听」无法执行；只有待确认条目有锚点。需要在报告 schema 里给每条要点加锚点（或按段落 id 定位）。
2. 稳定性只跑了 22:51 一场，**3×90 分钟**门槛仍未验证。
3. 延迟仍无 app 内打点（用 ADR-0008/0012 的代理数据）。

## 结论

v0.1 主干在真实课堂上**可用**（录音稳定、转写速率正常、校正与报告产出符合预期），但离 ADR-0007 的完整验收还差：报告要点锚点、3×90 分钟稳定性、延迟打点。
