# ADR-0013：移除离线二遍 ASR —— 终稿只保留 LLM 校正

- **状态**：已接受；**取代 [ADR-0010](0010-two-pass-text-policy.md) 的离线二遍实现**（「两稿并存不覆盖」的原则保留，只是第二稿从离线 ASR 换成 LLM 校正稿）
- **日期**：2026-11-19
- **相关**：ADR-0002（两遍转写）、ADR-0010（二遍稿文本策略）、ADR-0011（终稿 LLM 校正）

## 背景

ADR-0010 已经证明：离线 Paraformer 的二遍稿并不比实时稿好（相对校正稿 CER 0.325，而实时 1920ms 档只有 0.106）。而 ADR-0011 引入的 LLM 校正效果显著，并且**只需要文本，不需要音频**。

也就是说，终稿管线里同时存在两条「纠错」路径：

1. 离线 ASR 二遍（Paraformer，217 MB，需要读 WAV、逐段解码、加载 1–3 秒）；
2. LLM 校正（已经覆盖同音字、术语、变量名）。

第 1 条既不更准，又占 217 MB 模型空间、增加终稿耗时；它的唯一作用——给 LLM 提供第二份识别假设——收益远低于成本。用户也明确要求删掉这 217 MB。

## 决策

1. **删除离线二遍阶段**与 Paraformer 模型：终稿 = LLM 校正（基于实时稿 + 上下文 + 术语表）。
2. 删除 `OfflineAsrEngine`、`WavPcmReader` 与 `runOfflinePass` 代码；模型目录不再包含 Paraformer（设备上省 217 MB）。
3. `segment.offline_text` 列**保留**（历史数据兼容，不迁移、不写入新值）。
4. 「重跑终稿」现在只重跑 LLM 校正，因此不再要求存在音频文件，速度也从「读 WAV + 离线解码 + 校正」降到「只做校正」。
5. 「待确认」信号改为：**实时稿 vs 终稿（校正稿）**的分歧（`Segment.finalGuess`），而不是实时稿 vs 离线稿。

## 后果

**正面**

- 终稿更快（18 段实测重跑 ≤ 6 秒，原来要先跑离线解码）。
- 首启只需下载实时模型（163 MB），不再有第二份大模型。
- 代码更少：删掉一个 ASR 引擎与 WAV 分片读取器。

**负面 / 代价**

- 少了一份独立假设；如果实时稿把某个词完全听成另一个词、上下文也救不回来，校正也修不了。实测这类情况主要靠术语表 + 上下文缓解。
- 旧场次的 `offline_text` 变成只读历史字段（UI 已不再展示「二遍」，只展示「终稿」）。

## 复审触发条件

1. 出现体积小（<100 MB）且显著优于实时稿的离线中文模型——那时可以恢复二遍 ASR 作为校正的输入；
2. 有需要在无网络环境生成终稿的场景（当前校正依赖 LLM 网络）。
