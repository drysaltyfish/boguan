# ADR-0007：v0.1 范围、验收门槛与风险登记

- **状态**：已接受；**§2 的 CER 门槛测法已被 [ADR-0016](0016-acceptance-without-human-transcript.md) 调整**（项目所有者不做人工转写 → CER 暂缓，改用自动化指标；其余门槛保留）
- **日期**：2026-11-17
- **相关**：全部 ADR

## 1. v0.1 范围

**必须做**

- 录音（开始 / 暂停 / 结束）、四状态状态机
- 实时字幕（前台最新 6–10 行；**屏幕不长亮**；熄屏停渲染、只保录音）
- 端上流式转写（实时稿）
- 会后本地二遍转写（终稿）
- 类型选择（课堂 / 会议）+ 类型化微摘要
- 结构化报告：公共信封 + 类型载荷 → 课堂笔记 / 会议纪要两种渲染
- **锚点回听 + 低置信度实体高亮 + 待确认清单**
- 历史记录列表
- 设置：LLM provider / key、模型下载与管理、音频保留策略、更新检查
- 失败恢复：断网出无摘要版报告；LLM 调用可重放

**明确不做**

| 不做项 | 理由 |
|---|---|
| 说话人分离 | 课堂只需二值判断（二期）；会议完整 diarization 成本高且远场效果无公开数据 |
| 线上会议（系统回环音频） | **Android 平台硬限制**：`AudioPlaybackCapture` 被多数会议 App 禁用；要做必须桌面先行 |
| 云同步 / 账号体系 | 与「数据存本地」冲突 |
| 分享与导出（PDF / DOCX / MD 导出） | 「报告是投影」一旦可导出就会变成用户资产，需要版本与冲突处理 |
| 报告就地编辑 | 同上；用重新渲染代替 |
| 导入已有音频文件 | 需要解码链路（ffmpeg 未装），且非核心价值 |
| 多语言（仅中文） | 缩小验证面 |
| 桌面端 | 平台顺序为 Android 先行 |
| 插件系统 | 大后期；当前只保留 `AsrEngine` / `LlmProvider` / 类型注册表三个内部边界 |

## 2. 验收门槛

| 维度 | 门槛 |
|---|---|
| 实时延迟 | 说话 → 字幕 < **2 s** |
| 实时 CER | **8–12%**（自录课堂基准集） |
| 终稿 CER | **≤10%**（本地二遍） |
| 稳定性 | 连续 **3×90 分钟**无崩溃、无丢音、无断流 |
| 报告可信度 | 抽 20 条要点，**≥95%** 可回听到对应片段 |
| 待办可执行 | 主观评分 **≥70%** |
| 耗电 | **不做专项实测**（2026-11-18 决定，见 §5）；以设计约束与真机 RTF 数据代替 |

**基准集**：3 段真实课堂录音（10 / 30 / 90 分钟）+ 其中 10 分钟的人工转写 ground truth。**这是验收与模型选型的唯一量尺，缺失则门槛无法执行。**

4. ~~（触发式）**R1 清理**~~ ✅ **已关闭**：实时模型改为 Apache-2.0 的 X-ASR（ADR-0008）。

## 5. 明确不做实测的项

**90 分钟耗电与温升**（2026-11-18 项目所有者决定）。

- **原因**：技术尖峰已测出真机 RTF 0.085，折合 90 分钟课堂约 7.7 分钟 CPU、单核占用约 8.5%，功耗不再是最主要的风险；而完整 90 分钟实测的收益不足以抵消等待成本。
- **替代措施**：把功耗当作**设计约束**而非验收指标 —— 前台服务承载录音、熄屏停渲染、不做激进音频预处理、模型加载后常驻不重复加载。
- **残余风险**：真实课堂 90 分钟下的发热与掉电未量化，可能在实际使用中暴露（登记为 R7）。
