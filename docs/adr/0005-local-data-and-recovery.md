# ADR-0005：本地数据与失败恢复

- **状态**：已接受
- **日期**：2026-11-17
- **相关**：ADR-0003（幂等重放）、ADR-0004（信封与载荷）

## 背景

「数据存本地」是产品前提。现实约束：课堂 Wi-Fi 常常不可用、来电会抢麦克风、电量与存储会在 90 分钟里告急、LLM API 会超时。任何一条处理不好都会丢录音——这是这类 App 最不可接受的失败。

## 决策

### 1. 存储

SQLite（Room），六张表：

| 表 | 内容 |
|---|---|
| `session` | 一场记录：类型、时间、时长、音频源、状态 |
| `segment` | 转写段：实时稿 / 终稿（`is_final`）、时间戳、置信度 |
| `micro_summary` | 每 2 分钟的微摘要 + 每 10 分钟的结构整理（`kind` 区分），含降级标记 |
| `qa_pair` | 会中问答（问题、回答、时间锚点） |
| `report` | 渲染产物 + 生成时的类型 + 引用版本（可重生成） |
| `llm_call` | 每次 LLM 调用：prompt、response、request-id、usage、状态（幂等重放依据） |

类型载荷以 JSON 存放在 `report.payload_json`，同时保留信封字段以支持查询；**Schema 版本号随载荷一起存**，便于迁移。

### 2. 音频

| 阶段 | 格式 | 说明 |
|---|---|---|
| 录制 → 终稿成功 + 7 天 | **WAV** 16 kHz 单声道 | 约 **169 MB / 90 分钟** |
| 之后 | **Opus 64 kbps** | 约 **43 MB / 90 分钟**，保留回听能力 |
| 可选 | 「只留文本」开关（默认关） | 明确告知将失去回听能力 |

**不做云备份**。删除必须有二次确认。

### 3. 状态机

```
idle → recording ⇄ paused → finalizing → done
                                 ↘ failed(可重试)
```

- 暂停算**同一场**；暂停 > 20 分钟提示「继续这节课 / 开始新课」。
- 来电：麦克风被系统抢占 → 自动暂停并通知，挂断后可继续。
- 电量 ≤ 15% 或可用空间 < 2× 预估音频（90 分钟约 340 MB 余量）→ 提示并**自动保存当前进度**，不静默中断。

### 4. 失败恢复三条硬规则

1. **转写与摘要解耦**：录音与本地转写绝不依赖网络；摘要失败只进队列，不影响录音。
2. **LLM 调用可重放幂等**：每次调用持久化 prompt/response；重试不重复计费、不重复生成。
3. **断网也能出报告**：可生成「无摘要版报告」（元信息 + 转写全文 + 时间戳 + 锚点），网络恢复后补摘要并按需重新抽取。

## 后果

**正面**：录音几乎不可能因为网络或 API 失败而丢失；存储占用可预测；数据迁移有版本号可依。

**负面**：WAV 保留 7 天会占空间（90 分钟 ≈ 169 MB，多节课叠加），需在设置中显示当前占用并提供清理入口。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 直接存 Opus、不存 WAV | 终稿重跑与调试需要无损源；且回听纠错质量下降 |
| 原始音频只留 24 小时 | 用户回看并核对报告的窗口通常不止一天 |
| 微信/网盘式云备份 | 与「数据存本地」承诺冲突，且引入账号体系 |
