# ADR-0006：发布、许可与供应链

- **状态**：已接受
- **日期**：2026-11-17
- **相关**：ADR-0002（R1 权重许可）、ADR-0007（范围）

## 背景

产品开源、经 GitHub Releases 侧载分发，不上任何应用商店。因此不需要商店的软著/备案/审核，但需要自己处理：许可证、第三方署名、APK 签名、供应链安全、隐私说明。

## 决策

### 1. 许可

- **App 代码：Apache-2.0**（保留专利授权，且不放弃将来商业化或上架的选项）。
- **模型权重不随项目分发**（体积 + 上游许可不明）。
- `THIRD-PARTY-LICENSES.md` 逐一署名：sherpa-onnx（Apache-2.0）、ONNX Runtime（MIT）、SenseVoice（FunASR Model Open Source License v1.1，须署名并保留模型名）、以及所用模型的具体来源。

### 2. 分发与签名

- 仅通过 **GitHub Releases** 分发（APK + SHA-256 校验和 + changelog）。
- **签名密钥由作者离线保管**；公钥指纹写入 README 供用户校验 APK。
- **不申请 F-Droid**（其可复现构建要求会拖住迭代节奏，而分发不依赖它）。

### 3. CI/CD 供应链

- 构建与发布走 **GitHub Actions**，只有 `v*` tag 能触发发布 workflow（PR 与普通分支永远接触不到 secrets）。
- 签名 job 绑定**受保护的 GitHub Environment**，需**人工审批**后执行。
- **所有 action 锁定 commit SHA**，不用浮动 tag；不引入来源不明的第三方 action。
- **密钥泄露 = 数据丢失级事故**：Android 侧载应用的签名密钥无法无损轮换（换密钥 = 新 App，用户须卸载重装，而本应用数据全在本地）。因此上述三道闸门不可削减。

### 4. 更新

- 内置 GitHub Releases 版本检查：可关闭、失败静默、**只提示不自动安装**（侧载本来就需用户手动允许安装）。

### 5. 隐私与透明

- README 与设置页提供**数据流向说明**：音频与转写永不出设备；仅摘要文本发送到用户自行配置的 LLM endpoint。
- API key 存 Android Keystore，不上传、不写入日志。
- 权限最小化：仅 `RECORD_AUDIO` + 前台服务（麦克风类型）；不申请通讯录、存储读写等无关权限。

## 后果

**正面**：许可清晰、供应链可控、用户可校验 APK、隐私承诺可审查。

**负面**：每次发版需要人工点一次 approve；R1 的许可问题在**转为公开发布前必须清理**（当前以自用为主，风险已接受）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 上架国内应用商店 | 软著/备案/审核会拖住技术验证，且与「先给自己用」的现状不符 |
| 签名也完全自动化（无审批） | 任何能推 tag 的人即可拿到签名密钥，风险不可接受 |
| 本地手工签名上传 | 可行但违背「自动发布」的诉求，作为 Q34 的备选已记录 |
