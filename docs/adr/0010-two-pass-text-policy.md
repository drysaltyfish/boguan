# ADR-0010：二遍稿的文本策略 —— 并存、不覆盖、以分歧驱动待确认

- **状态**：已接受；**取代 [ADR-0002](0002-asr-pipeline.md) 决策中的「会后本地非流式纠错（覆盖）」一条**；**离线二遍的具体实现已被 [ADR-0013](0013-remove-offline-pass.md) 取代**（「两稿并存、不覆盖」原则保留，第二稿改为 LLM 校正稿）
- **日期**：2026-11-18
- **相关**：ADR-0002（ASR 管线）、ADR-0004（待确认清单）、ADR-0005 / ADR-0009（存储）、ADR-0008（实时模型改版）

## 背景

按 ADR-0002 / ADR-0008，终稿二遍用 SenseVoice-Small int8 重跑实时段落并**覆盖**段文本。实现后真机实测：

- 一场 110 秒课堂录音（行列式课程，远场 4 m），7 段全部被离线稿覆盖，界面显示「终稿完成（校正 7/7 段）」；
- 但覆盖后**文本变差**：实时稿「…A 一一在 C 中的**余子式**」→ 离线稿「…A 一一在 C 中的**女子是**」；「公式」→「公西」；整段无标点（SenseVoice 该权重不输出标点）。

随后在**三段真实录音、17 个段落**上做对照（同一 sherpa-onnx 2.0.1、同一音频切片、桌面 CPU 解码，与实时稿按「去标点/空白的字级相似度」对比）：

| 离线模型 | 体积 | 与实时稿平均相似度 | 观感 |
|---|---|---|---|
| SenseVoice-Small int8 2025-09-09 | 228 MB | **0.671** | 术语换字多（余子式→女子是/鱼子式），全大写英文，无标点 |
| Paraformer-zh int8 2024-03-09 | 217 MB | **0.710** | 术语明显更稳（余子式/矩阵/行列式多处正确），中英混说更接近实时稿 |

两个离线模型**都没有稳定优于**实时流式模型（X-ASR 480ms）：三者各有错处，实时稿至少带标点且与段落边界对齐。结论是：**在本数据上没有任何依据说「离线稿更好」，直接覆盖等于用更差的文本替换可用的文本**。

## 决策

1. **两稿并存，不覆盖**：`segment.text` 始终保留实时稿；二遍结果写入新列 `segment.offline_text`（DB_VERSION 3）。
2. **展示文本单点决定**：`Segment.displayText` → `TranscriptMerge.displayText(realtime, offline)`。v0.1 返回实时稿；将来换到验证更优的离线模型时只改这一个函数，不动数据层与 UI。
3. **分歧驱动「待确认」**：`TranscriptMerge.needsReview` 用归一化字级相似度判定，阈值 0.85（≈15% 以上字符不一致）。历史详情页据此生成**待确认清单**：按相似度升序取前 5 段，实时稿与二遍稿并排显示，点「回听」核对。这就是 ADR-0004 里「待确认清单」的数据来源。
4. **离线引擎选型**：默认 **Paraformer-zh int8**（本轮实测更稳）；`OfflineAsrEngine` 按目录名识别 `paraformer` / `sense-voice` 两种模型，优先 Paraformer，SenseVoice 保留作备选与对照。
5. **v0.1 不引入标点模型**：CT-Transformer 标点模型 281 MB，只在离线稿要当展示文本时才有意义，暂时省掉这份体积与加载时间。

## 后果

**正面**

- 二遍管线出错时不再破坏用户已经看到的文本（可回退、可对比）。
- 两份独立解码的分歧天然是「需要人耳确认」的信号，比单一置信度更可靠，直接喂给 ADR-0004 的待确认清单。
- 模型替换被隔离在 `TranscriptMerge.displayText` 一个函数里，换模型不必迁移数据。

**负面 / 代价**

- 存储约翻倍（转写文本本身很小，可忽略）。
- 用户看到「待确认 N 段」但没有「终稿已校正」的确定感——这是诚实的代价。
- 二遍稿若长期不用，会被怀疑是死代码；因此它必须承担（3）的待确认清单职责。

## 复审触发条件

出现下列任一情况时重新评估，并（若结论翻转）在此 ADR 上追加而不是新开一份：

1. 有离线模型在**至少 3 场真实课堂录音**上，相对实时稿的 TER（用人工校正稿作参考）显著更低（例如相对下降 ≥20%）；
2. 引入更强算力/更大模型（如 FireRedASR2-AED）后仍满足端上时延与体积约束；
3. 有句子级置信度可用，可替代「两稿分歧」作为待确认信号。
