# ADR-0011：终稿 LLM 校正 —— 用语言模型修 ASR 的同音错

- **状态**：已接受；**修改 ADR-0002 的隐私表述**（"只把摘要文本发往 LLM 端点" → 转写文本也会发往该端点做终稿校正）
- **日期**：2026-11-19
- **相关**：ADR-0002（ASR 管线）、ADR-0003（LLM 抽象与降级）、ADR-0010（二遍稿文本策略）

## 背景

真机试用反馈：**实时转写与二遍纠错的效果都太差**。逐段核对三方输出（实时稿 / 离线二遍 / 人工判读）后确认，差的不是「没听清」，而是**同音字与术语**：

| 音频里说的 | 实时稿 | 离线二遍 |
|---|---|---|
| 余子式 | 余值式 / 离子阵 | 余子式 / 子式 |
| 代数余子式 | 大于单独 | 单数原子式 |
| 公式 | 公西 | — |
| a_{n-1} | a 减一 | a 减一 |
| j | 债 / 此当 | — |

这类错误靠换 ASR 模型解决不了（中文远场 + 专业课术语是长尾），但**语言模型可以**：它知道「行列式课上 A 一一在 C 中的余子式」里那个词必须是「余子式」。

真实课堂录音上的实验（16 段，两场课）：把「实时稿 + 离线稿 + 前后文 + 术语表」交给 LLM，要求只改识别错误、不改写不总结，结果：

- `女子是 → 余子式`、`鱼子式/原子式 → 余子式`、`公西 → 公式`、`大于单独 → 代数余子式`
- `债不等于 T → j 不等于 1`、`A 一二 → A_12`、`一行 B N 减一列 → 第 n 减一列`
- 小样本成本：6 段 ≈ 763+512 tokens ≈ ¥0.001；推算 90 分钟 ≈ ¥0.03

## 决策

1. **新增第三份文本**：`segment.corrected_text`（DB_VERSION 4）。三份文本并存，互不覆盖：
   `text` 实时稿 / `offline_text` 离线二遍稿 / `corrected_text` LLM 校正稿。
2. **展示优先级**：校正稿 > 实时稿 > 离线稿（`TranscriptMerge.displayText` 单点决定）。报告与摘要都走展示文本。
3. **校正方式**：每批 12 段，附前后各 2 段作为上下文，附带设置里的**术语表**；要求严格 JSON（`i` + `text`），只写校正稿，不覆盖原稿。单批失败只跳过该批（ADR-0003 L4 风格的局部降级），不影响终稿其余部分。
4. **可开关、可重跑**：设置里「终稿校正」默认开；历史详情有「重跑终稿」（重跑离线二遍 + 校正），不依赖录音时是否在线。
5. **隐私边界更新（重要）**：音频仍然**永不**离开设备；但**转写文本**除摘要外，也会发往用户自己配置的 LLM 端点做校正。设置页与 README 必须如实写明，且该开关可关。这与 ADR-0002「只有摘要文本外发」的表述不同，本条取代那一句。

## 后果

**正面**

- 感知质量提升最大的一次改动：术语、变量名、数字层面的错误被系统性修掉，报告的事实基础也随之变好。
- 与 ASR 解耦：换 ASR 模型、换离线模型都不影响校正层。
- 成本可忽略（90 分钟约 ¥0.03，对比摘要 ¥0.5–2）。

**负面 / 代价**

- 隐私面扩大：转写全文会发往 LLM 端点（音频仍不出设备）。用户可关闭。
- 校正依赖网络与 LLM 可用性；不可用时保留实时/离线稿，功能不退化。
- 校正可能「过度修正」：prompt 明确禁止增删与改写，但仍有风险，因此三份原稿都保留，可随时重跑/对照。
- 每 90 分钟约 13 次额外调用。

## 复审触发条件

1. ASR 侧（热词/同音替换/更大模型）把同音错降到不需要 LLM 也能读的程度；
2. 用户明确要求「转写文本也不许出设备」——那时改为纯本地同音替换（sherpa-onnx HomophoneReplacer + 拼音词典）；
3. LLM 端点支持更便宜的长上下文批处理时，可把 12 段/批提高以进一步降本。
