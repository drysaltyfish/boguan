# ADR-0012：实时转写档位 —— 用 1920 ms 分块换准确率

- **状态**：已接受；**部分取代 ADR-0008 的「默认 480 ms」选型**
- **日期**：2026-11-19
- **相关**：ADR-0002（ASR 管线）、ADR-0008（实时模型改版）、ADR-0011（LLM 校正）

## 背景

用户反馈实时转写效果差。按「本地可做的改进」逐项实测（一加 12、真实课堂录音 18 段，参考文本用 LLM 校正稿，CER = 归一化字级编辑距离）：

| 方案 | 相对校正稿 CER | 结论 |
|---|---|---|
| 实时 X-ASR **480 ms**（当时默认） | **0.159** | 基线 |
| 实时 X-ASR **1920 ms** | **0.106** | 相对降 **33%**，可用 |
| 离线 Paraformer-zh int8（逐段重跑） | 0.325 | 比两个流式模型都差（再次印证 ADR-0010 不覆盖实时稿） |

顺带试过的本地手段：

- **hotwords（热词偏置）**：AAR 支持 `hotwordsFile/hotwordsScore`，但 sherpa-onnx 要求 `modified_beam_search` 且热词需按 BPE 编码；X-ASR 的 tokens 是 BPE（`▁余` 这类），热词编码报 `Cannot find ID for token 余`，全部被跳过（热词无效），同时 beam search 更慢。**结论：不可用**，已放弃。
- **同音替换（HomophoneReplacer）**：需要额外的拼音词典与规则 FST，而且实测的高频错误（`女子是` vs `余子式`）不是同音关系而是近音/连读，规则替换收益有限。**结论：暂不做**，由 LLM 校正（ADR-0011）覆盖。

## 决策

1. **默认实时档位改为 1920 ms**（`X-ASR 1920ms` 模型），因为本产品是「读文本」场景，33% 的相对错误下降比 0.5 秒首字延迟更重要。
2. **设置里可选 480 ms**（更低延迟）：`实时转写档位` 两项，改动后重启应用生效。
3. 两个模型目录都保留在设备上（各约 170 MB），由设置选择；引擎在启动时按档位挑目录。

## 后果

**正面**

- 实时稿错误率下降三分之一；LLM 校正的输入质量同步变好。
- 用户可按场景（听力/记笔记 vs 需要即时文字）自行权衡。

**负面 / 代价**

- 首字延迟从 1.60 s 升到约 2.10 s，**略微超出 ADR-0007 的 <2 s 门槛**——接受，因为实时余量仍充足（RTF 0.046，21.6×）。
- 设备上多占约 170 MB 模型空间。
- 测量只有一场 18 段真实录音，且参考文本来自 480 ms 稿的校正结果（对 480 有利），1920 的真实优势可能被低估；后续可用人工校正稿复核。

## 复审触发条件

1. 出现同等错误率但更低延迟的流式模型（如新的 chunk 方案）；
2. 用户反馈「首字太慢」超过「准确率不够」。
